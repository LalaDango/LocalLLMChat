#### e4bの挙動特性（モデル特性なのでLocalLLMChatにも示唆あり）

- **位置指定はとり違え・名指しは当たる**: 高占有帯（72/82/90%で実証）で「直近3件」等の
  位置参照は毎回とり違え。同じ内容をタイトルで名指しすると全問正解。
  「忘れるのではなく、数えられない」（SWA512の遠距離位置分解能限界説が有力）
- **ただし添付文書内の位置参照は16K/49%占有まで無傷**（2026-07-06、8/8満点）:
  「とり違え」は高占有域（72%超）＋**会話履歴の件数カウント**（「直近3件」等）の現象で、
  **単一文書内の位置参照とは別物**。文書内なら先頭・末尾・離れた2箇所の横断まで正確。
  劣化開始帯は占有49%〜72%の間のどこか（未検証）。劣化はまず「近くの別の数値との取り違え」として
  出る想定なので、誤答時はどの数字を持ってきたかで劣化帯域を推定できる
- **画像内文字の読解限界は原寸12〜14px相当**（解像度ラダー実測）。レシートの12px fine printまでは
  満点で読めるが、**境界サイズでは「読めた風」の幻覚コードを出す**（テスト字種に無いはずの文字を
  出力した実績あり）。完全に読めない場合は正直にunreadableと言うので、**半端に潰れた文字が一番危ない**。
  画像OCRの数値をそのまま信用しないこと
- グラフの数値読み取りは~50%程度で**系列取り違え癖**あり（解像度と無関係のモデル特性）。
  表・レシートのような整列テキストは得意、プロット上の値対応付けは苦手

## 新モデル評価テンプレート

新しいモデルについて聞かれたら以下を確認:

```
□ パラメータ数: ___B
□ 量子化後サイズ (Q4系): ___GB
□ 同系統の実測NPUピークからの見積り < 9.1GB（Windows AI 2〜3GBの割り込み余地も考慮）: YES / NO
□ FLMプロセスRAM見積り（12Bで8〜9.7GB）＋OS が15.2GB内か: YES / NO
□ FastFlowLM対応アーキテクチャか（model_list.json の flm_min_version も確認）: YES / NO / 未確認
□ NPU最適化フォーマット有無: YES / NO / 未確認
□ 想定コンテキスト長: ___トークン
□ KVキャッシュ見積り: ___GB
□ ※ファイルサイズ＝NPU使用量ではない（12B: 9.32GB→ピーク7.2〜8.3GB）。ctx-lenはNPUよりRAMに効く
□ checkpoint挙動: 生成後保持型(e4b型) / 非保持型(9B・12B型) / 未確認
→ 判定: ✅動作可能 / ⚠️条件付き / ❌不可 / ⏳情報不足
```
